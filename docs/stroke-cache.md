# 스트로크 캐싱: 다 쓴 획은 한 장의 그림으로

**완료된 획은 배경 사진처럼 보관하고, 입력할 때는 그 사진 위에 작성 중인 획만 다시 그린다.**

[Archify 설명 문서 열기](../playground/public/analysis/stroke-cache.html). HTML 파일을 브라우저에서 바로 열거나, `vp run playground` 실행 후 상단의 `스트로크 캐싱 설명`을 누른다. 기존 분석 문서와 별도로 만든 문서다. 설명은 한국어이며 Viewer 기본 UI와 HTML 언어는 영어 fallback을 사용한다.

## 100개 획을 쓴 다음 101번째를 쓴다면

이전에는 펜이 움직일 때마다 기존 100개와 작성 중인 101번째 획을 모두 다시 그렸다. 필압 획은 점마다 굵기와 윤곽을 계산하므로, 필기가 쌓이면 새 획을 그리는 일도 무거워졌다.

캐싱을 도입한 `362ba01`(v0.1.55)부터는 기존 획을 한 장의 그림으로 보관했고, v0.1.75부터는 그 그림을 앱 캔버스 **아래에 겹친 층**으로 둔다.

1. **기존 100개:** `committedCanvas`에 한 장의 그림으로 보관한다. 이 캔버스는 앱 캔버스 바로 앞 형제로 DOM에 붙고, `position: absolute`와 `pointer-events: none`으로 앱 캔버스와 같은 자리에 겹친다.
2. **펜 이동:** 앱 캔버스(`desynchronized`)를 비우고 작성 중인 `current` 획만 그린다. 다음 프레임을 기다리지 않고 입력 이벤트를 처리하면서 바로 그린다. 두 층을 합치는 일은 브라우저 합성기가 맡는다.
3. **펜을 뗄 때:** 캐시가 유효하면 방금 완성한 101번째 획을 **마르는 층**(`dryingCanvas`)으로 보낸다. 앱 캔버스에서는 바로 지우지 않고 **마르기 시작할 때(0.5초)까지 함께 그려 둔다.** 일반 캔버스인 마르는 층은 앱 캔버스(`desynchronized`)보다 늦게 화면에 나오므로, 바로 지우면 그사이 획이 한 프레임 사라진다(v0.1.83에서 실제 필기 녹화로 확인). 두 층 모두 불투명하게 보이는 상태라 겹쳐 있어도 변하지 않는다.
4. **잉크가 마를 때:** 마르는 층의 획은 0.5초 뒤부터 1초에 걸쳐 불투명에서 원래 반투명으로 바뀐다. 다 마르면 그 순간 `committedCanvas`에 덧그리고 마르는 층에서 뺀다. 다음 입력부터는 101개 획이 담긴 그림을 재사용한다.

캐싱하는 것은 **완료된 획들의 렌더링 결과**다. 원본 `strokes`의 점·필압·스타일도 계속 보관하므로 지우기와 되돌리기를 할 수 있다. `committedCanvas`는 일반 `HTMLCanvasElement`이며, Worker나 `OffscreenCanvas` API를 사용하는 구조는 아니다.

### 왜 아래에 겹쳤나 (v0.1.75)

v0.1.74까지는 `committedCanvas`를 화면에 붙이지 않고, 펜 이벤트마다 앱 캔버스를 비운 뒤 `drawImage`로 화면 크기 그림을 통째로 복사했다. P580(1152×1454, DPR 1.5)에서는 이벤트마다 약 380만 픽셀을 복사하는 셈이다. 이 복사를 없애자 같은 조건의 자동 재생 측정(각 6회)에서 25ms를 넘는 프레임 간격이 **5.1%에서 1.0%로** 줄었고, 두 조건의 실행별 범위(3.6–5.9% / 0.4–2.2%)도 겹치지 않았다. JS 처리 시간은 거의 같다. 이득은 GPU 쪽 복사가 사라진 데서 나온다.

**대가:** 앱이 캔버스 자체에 배경을 칠하면 그 배경이 아래 층의 획을 가린다. 배경은 캔버스를 감싼 요소에 칠한다(플레이그라운드는 모눈을 `.canvas-stage`에 둔다). 앱 캔버스가 `position: static`이면 아래 층보다 위에 오도록 `position: relative`를 넣고 `destroy()`에서 되돌린다. 아래 층의 위치는 캔버스 크기가 바뀔 때(`resize`) 맞추므로, 크기는 그대로인 채 캔버스만 옮겨지는 레이아웃은 아직 따라가지 않는다.

### 쓰는 중에는 불투명, 다 쓰면 서서히 반투명 (v0.1.82)

획은 반투명(기본 0.7)이다. 문항 위에 써도 인쇄된 글자가 비쳐 보여야 하기 때문이다. 그런데 반투명 획을 앱 캔버스(`desynchronized`)에서 아래 층으로 넘기면, 두 층이 화면에 나가는 시점이 달라 같은 획이 잠깐 겹쳐 **진해지거나**(늦게 지울 때) **사라진다**(일찍 지울 때). 두 경로는 맞출 수 없다.

그래서 획 모양대로 배경색을 먼저 깔고 그 위에 반투명 잉크를 칠한다(`drawInk`). 배경을 다 깔면 바탕 위에 반투명으로 칠한 것과 같은 색의 불투명 획이 되어, 두 층에 겹쳐도 변하지 않는다. 쓰는 중과 마르기 전에는 배경을 다 깔고, 마르는 동안 배경의 진하기를 0으로 줄인다. 바탕 위의 색은 그대로이고, 교차점과 그 아래 글자만 잉크가 마르듯 서서히 비쳐 나온다.

- **층 순서:** 다 쓴 획 층 → 마르는 층 → 앱 캔버스. 마르는 층과 다 쓴 획 층은 둘 다 일반 캔버스라, 다 마른 획을 옮길 때 같은 프레임에 함께 바뀐다.
- **배경색:** 투명하지 않은 배경을 가진 가장 가까운 조상의 색을 쓴다. 필기 중 스타일을 읽지 않도록 `resize`에서만 잰다.
- **다 쓴 획 층을 통째로 다시 그릴 때**(지우기·되돌리기·크기 변경): 마르던 획도 그 안에 들어가므로 마르는 층을 비운다.
- **마르기 전 대기 중:** 모습이 그대로이므로 마르는 층은 새 획이 들어올 때만 다시 그린다.
- **P580 확인:** 교차점 밝기가 펜을 뗀 지 약 0.6초 뒤부터 0.9초에 걸쳐 149에서 121로 단계적으로 진해졌다. 72획 자동 재생 녹화에서 획이 진해지거나 사라지는 프레임은 없었다.

## 보관된 그림이 낡으면 어떻게 하나

`committedDirty`는 “완료된 획의 그림을 다시 만들어야 하는가?”를 나타낸다.

| 상황                                     | 처리                                        |
| ---------------------------------------- | ------------------------------------------- |
| 펜으로 새 획을 쓰는 중                   | 캐시 재사용 + 현재 획 전체 다시 그리기      |
| 펜을 뗌, 캐시가 유효함                   | 새로 완성된 획만 캐시에 추가                |
| 펜을 뗌, 캐시가 무효함                   | 추가를 건너뛰고 종료 후 전체 재생성         |
| 지우개가 실제 획을 바꿈                  | `committedDirty = true`                     |
| undo·redo·clear·setStrokes로 획을 교체함 | `committedDirty = true`                     |
| 초기 표시 또는 resize                    | 캔버스 크기와 DPR을 맞추고 전체 재생성      |
| 아무것도 지우지 않은 지우개 이동         | 캐시 재사용                                 |
| 도구·펜 스타일 변경                      | 캐시 재사용. 기존 획은 각자의 스타일을 유지 |

무효화된 캐시는 다음 `redraw()`에서 완료된 획 전체로 다시 만들고 `committedDirty = false`로 바꾼다. 작성 중인 획은 `strokes`의 마지막에 있지만, 캐시 재생성에서는 제외한다. 화면에 현재 획을 별도로 그릴 때 중복되지 않게 하기 위해서다.

지우개는 원본 획을 조각으로 바꾸므로 캐시를 다시 만들어야 한다. 이동 중에는 여러 입력을 `requestAnimationFrame` 한 번의 그리기로 모으고, 제스처 종료 시에는 즉시 반영한다. 빈 곳을 지날 때는 원본이 바뀌지 않아서 재생성이 필요 없다.

## 줄어든 비용과 남아 있는 비용

- **줄어든 것:** 평소 펜 입력마다 기존 획 전체의 점·필압·윤곽을 다시 계산하고 그리는 비용.
- **줄어든 것(v0.1.75):** 펜 입력마다 화면 크기 그림을 복사하는 비용.
- **남아 있는 것:** 작성 중인 획 전체를 그리는 비용. 마지막 선분만 추가하는 방식은 아니므로, 아주 긴 한 획은 여전히 무거워질 수 있다. 글씨는 획이 짧아 문제가 되지 않는다.
- **대가:** 화면용 캔버스 외에 캐시용 캔버스 메모리가 추가된다. 캐시 픽셀 수는 대략 화면 면적 × DPR²에 비례한다. 지우기나 크기 변경 시 전체 재생성 비용도 남는다.

기존 테스트는 펜 입력 중 완료된 획 층을 다시 그리지 않는지, 지우기·되돌리기에서 다시 그리는지, 빈 곳을 지울 때 재사용하는지를 확인한다.

## 되돌리기 이력 최적화는 별개다

후속 커밋 `6013b96`(v0.1.58)은 펜을 처음 댈 때의 비용을 줄였다. 이전 상태를 저장할 때 모든 점을 깊게 복사하는 대신 **배열만 복사하고 완료된 획 객체는 공유**한다.

완료된 획은 직접 수정하지 않고, 지우개도 원래 획 대신 새 조각을 만들기 때문에 가능한 방식이다. 화면 캐시는 “같은 그림을 다시 계산하지 않기”, 이력 최적화는 “같은 획 데이터를 반복 복사하지 않기”다. 외부로 주는 `getStrokes()` 복사본과 외부 입력을 받는 `setStrokes()`의 깊은 복사는 유지된다.
