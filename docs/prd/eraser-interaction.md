# 지우개 상호작용 PRD

- 상태: 구현 및 검증 중
- 기준 버전: 0.0.4
- 대상: 터치와 스타일러스를 동시에 사용하는 드로잉 플레이그라운드

## Problem Statement

사용자는 왼손으로 플로팅 도구 모음을 조작하면서 오른손의 스타일러스로 자연스럽게 필기하고 싶다. 그러나 손가락 터치가 간헐적으로 선택되지 않거나, 손가락을 지우개 아이콘에 계속 대고 있는데도 스타일러스 한 획이 끝난 뒤 펜으로 돌아가는 문제가 있다.

브라우저는 손가락과 스타일러스 입력을 각각 Pointer Events와 Touch Events로 전달하며, 팜 리젝션 과정에서 손가락 스트림을 취소하거나 입력 식별자를 재사용할 수 있다. 따라서 단순히 숫자 식별자나 스타일러스 획 종료만으로 손가락 해제를 판단하면 안 된다.

## Solution

지우개는 영구 선택과 순간 사용을 한 버튼에서 제공한다.

| 사용 동작                                                   | 결과                                          |
| ----------------------------------------------------------- | --------------------------------------------- |
| 지우개를 짧게 터치하고 캔버스를 사용하지 않음               | 지우개를 계속 선택한다.                       |
| 지우개를 손가락으로 누른 채 스타일러스로 지움               | 손가락이 닿아 있는 동안 지우개를 유지한다.    |
| 지우개를 누른 채 여러 획을 지움                             | 획 수와 관계없이 지우개를 유지한다.           |
| 순간 지우개를 사용한 뒤 지우개 아이콘에서 손가락을 뗌       | 즉시 펜으로 돌아간다.                         |
| 손가락 입력에 `pointercancel` 또는 `touchcancel`이 발생함   | 실제 손가락 해제로 간주하지 않는다.           |
| 스타일러스 획이 끝남                                        | 손가락 해제로 간주하지 않는다.                |
| 스타일러스 종료 이벤트가 손가락과 같은 숫자 식별자를 사용함 | 손가락 해제로 간주하지 않는다.                |
| 지우개 아이콘 밖에서 입력이 끝남                            | 손가락 해제로 간주하지 않는다.                |
| 펜 아이콘을 직접 선택함                                     | 지우개 순간 사용 상태를 끝내고 펜을 선택한다. |

손가락과 스타일러스의 입력 출처를 별도로 추적한다. 손가락 접촉을 시작한 입력 출처와 식별자가 모두 일치하는 실제 손가락 종료만 순간 지우개의 종료 조건으로 인정한다.

## User Stories

1. 왼손잡이 보조 조작 사용자로서 왼손으로 지우개를 누르고 오른손으로 스타일러스를 사용하고 싶다. 그래야 필기 흐름을 끊지 않고 지울 수 있다.
2. 스타일러스 사용자로서 지우개를 누르는 즉시 지우개가 활성화되길 원한다. 그래야 별도의 탭 완료를 기다리지 않고 바로 지울 수 있다.
3. 스타일러스 사용자로서 손가락을 지우개에 대고 있는 동안 여러 획을 연속으로 지우고 싶다. 그래야 매 획마다 지우개를 다시 선택하지 않아도 된다.
4. 스타일러스 사용자로서 스타일러스 한 획이 끝나도 지우개가 유지되길 원한다. 그래야 손가락을 계속 누르고 있다는 의도가 보존된다.
5. 스타일러스 사용자로서 지우개 아이콘에서 손가락을 뗀 순간 펜으로 돌아가길 원한다. 그래야 별도로 펜 버튼을 누르지 않고 필기를 이어갈 수 있다.
6. 일반 터치 사용자로서 지우개를 짧게 탭하면 지우개가 영구 선택되길 원한다. 그래야 여러 번 나누어 지우는 일반적인 사용도 가능하다.
7. 일반 터치 사용자로서 지우개를 탭하기만 하고 캔버스를 사용하지 않았다면 펜으로 자동 복귀하지 않길 원한다. 그래야 단순 도구 선택이 순간 사용으로 오인되지 않는다.
8. iPad 사용자로서 팜 리젝션이 입력 스트림을 취소해도 선택한 도구가 임의로 바뀌지 않길 원한다. 그래야 기기별 이벤트 차이 때문에 필기가 중단되지 않는다.
9. 스타일러스 사용자로서 스타일러스의 Touch 이벤트가 손가락 이벤트로 오인되지 않길 원한다. 그래야 펜을 떼는 동작이 순간 지우개를 종료하지 않는다.
10. 사용자로서 손가락과 스타일러스가 같은 숫자 식별자를 재사용해도 올바른 도구가 유지되길 원한다. 그래야 브라우저 내부 식별자 관리 방식에 영향을 받지 않는다.
11. 사용자로서 펜 버튼을 직접 선택하면 언제든 순간 지우개 상태를 취소하고 펜으로 돌아가길 원한다. 그래야 자동 동작과 관계없이 명시적으로 도구를 바꿀 수 있다.
12. 키보드 사용자로서 도구 버튼을 키보드로 선택할 수 있길 원한다. 그래야 터치 외 입력 방식에서도 같은 도구 상태를 사용할 수 있다.
13. 사용자로서 현재 선택된 도구가 짙은 파란색으로 즉시 표시되길 원한다. 그래야 입력이 정상적으로 인식됐는지 바로 확인할 수 있다.
14. 테스터로서 현재 배포된 버전을 화면에서 확인하고 싶다. 그래야 수정본이 기기에 반영됐는지 판단할 수 있다.
15. 유지보수자로서 동작 변경마다 패치 버전이 증가하길 원한다. 그래야 사용자 테스트 결과를 정확한 코드 버전과 연결할 수 있다.

## Implementation Decisions

- 순간 지우개 상태는 도구 모음 이벤트 코드와 분리된 작은 상태 모듈로 관리한다.
- 상태 모듈은 활성 접촉의 입력 출처와 식별자를 함께 저장한다. 숫자 식별자만으로 서로 다른 입력 장치를 비교하지 않는다.
- 손가락 입력은 `finger`, 그 외 마우스·스타일러스 Pointer 입력은 `pointer` 출처로 구분한다.
- Touch 이벤트의 `touchType`이 `stylus`이면 손가락 누름과 해제 판정에서 제외한다.
- 손가락 해제 이벤트를 처리할 때 동일한 손가락이 활성 Touch 목록에 남아 있으면 종료하지 않는다.
- 입력 종료 좌표가 지우개 아이콘 영역 안에 있을 때만 순간 지우개 홀드를 종료한다.
- `pointercancel`, `touchcancel`, 스타일러스 획 종료는 상태를 종료하지 않는다.
- 순간 지우개 사용 여부는 지우개를 누른 상태에서 캔버스 입력이 시작됐는지로 판단한다.
- 실제 손가락 해제 시 순간 지우개를 사용했다면 펜을 선택한다. 사용하지 않았다면 지우개 선택을 유지한다.
- 도구 모음의 손가락 입력은 `click`을 기다리지 않고 `touchstart`에서 처리한다.
- 펜·지우개·설정 등 도구 모음 버튼은 `pointerdown`과 `touchstart`를 함께 받는다. 스타일러스가
  둘 중 어느 쪽으로 들어올지 기기마다 달라, 한쪽만 걸러 받으면 특정 기기에서 스타일러스나
  손가락 입력이 아예 무시된다. 대신 누름·해제 처리를 중복 호출에 안전하게 만들어(상태
  모듈의 `press`는 있는 값을 덮어쓰고, 해제는 `matches()`가 이미 끝난 접촉을 걸러낸다) 두
  이벤트가 겹쳐 들어와도 결과가 달라지지 않게 한다.
- 되돌리기·다시 실행·전체 지우기·설정처럼 상태를 토글하거나 누적하는 일반 버튼은 중복 호출이
  안전하지 않으므로(같은 입력이 두 번 들어오면 두 번 실행된다), 짧은 시간창으로 중복 호출을
  걸러낸 뒤 실행한다.
- `Touch.touchType`은 Safari 전용 확장이라 Chrome·Android WebView의 `Touch`에는 아예 없다.
  이 값이 없다고 손가락으로 단정하면, 그런 브라우저에서는 스타일러스 Touch까지 손가락으로
  오판해 Pointer Events 기반 판정과 같은 접촉을 두고 서로 다른 결론을 내며 경쟁한다(도착
  순서에 따라 결과가 들쭉날쭉해진다). 그래서 `touchType`을 실제로 구분할 수 있는 브라우저인지
  먼저 확인하고, 못 하면 Touch 기반 손가락 판정 리스너 자체를 붙이지 않는다 — 그 브라우저의
  손가락·스타일러스 구분은 Pointer Events의 `pointerType`만으로 한다.
- 패키지 버전을 단일 진실의 원천으로 사용하며 화면 상단 버전 표시는 같은 값을 빌드 시 가져온다.
- 이번 변경은 `0.0.4`이며, 이후 사용자에게 전달되는 동작 수정마다 SemVer 패치 번호를 1씩 올린다.

## Testing Decisions

- 테스트는 내부 필드가 아니라 외부에서 관찰 가능한 도구 전환 결과를 검증한다.
- 순간 지우개 상태 모듈을 단위 테스트한다. 손가락 탭, 순간 지우개 사용, 여러 획, 취소 이벤트, 입력 출처 충돌을 각각 검증한다.
- 같은 숫자 식별자를 가진 스타일러스 종료가 손가락 홀드를 해제하지 않는 회귀 테스트를 유지한다.
- 지우개 아이콘 밖에서 끝난 입력이 손가락 홀드를 해제하지 않는 회귀 테스트를 유지한다.
- 손가락 해제 전 여러 번 스타일러스 획 종료가 발생해도 지우개가 유지되는지 검증한다.
- 손가락 해제 후에는 순간 지우개 사용 여부에 따라 펜 복귀 또는 지우개 유지가 정확히 나뉘는지 검증한다.
- 기존 편집기 테스트 방식과 동일하게 빠르고 결정적인 단위 테스트를 우선한다.
- 실제 iPad와 스타일러스 조합에서는 왼손으로 지우개를 누른 채 오른손으로 최소 세 획을 지운 후 손을 떼는 수동 승인 테스트를 수행한다.
- 배포 워크플로에서 포맷, 타입 검사, 전체 테스트, 플레이그라운드 빌드를 통과해야 한다.

## Out of Scope

- 스타일러스 측면 버튼이나 더블 탭을 지우개 전환에 연결하는 기능
- 지우개 버튼을 누르지 않은 상태에서 팜 입력을 별도 제스처로 사용하는 기능
- 손가락으로 캔버스에 직접 필기할 때의 팜 리젝션 정책 변경
- 지우개 모양, 색상, 애니메이션의 추가 디자인 변경
- 도구 선택 상태의 영구 저장 또는 기기 간 동기화
- 라이브러리 공개 API에 순간 지우개 상태를 추가하는 작업

## Further Notes

- 웹 브라우저가 취소한 손가락 스트림에서는 물리적인 접촉 상태를 완전히 관찰할 수 없으므로, 취소 이벤트 자체를 해제 신호로 사용하지 않는다.
- 버전 표시는 사용자가 캐시된 이전 배포본과 수정된 배포본을 구분하기 위한 승인 기준이다.
- 이 PRD는 로컬 문서로만 관리하며 이슈 트래커에는 게시하지 않는다.
- **미해결 위험**: 일부 S펜 지원 안드로이드 기기(예: 삼성 갤럭시탭 A 계열)에서 스타일러스로
  그리거나 지운 직후 손가락으로 도구 아이콘을 눌렀을 때 간헐적으로 반응하지 않는 현상이
  보고됐다. 같은 아이콘을 스타일러스로 누르면 항상 바뀌고, 스타일러스를 전혀 쓰지 않았을
  때도 손가락이 항상 바뀐다 — 실패는 "손가락 사용 직후"에만, 그것도 간헐적으로 일어난다.
  코드에는 이 지연을 설명할 타이머나 잠금 상태가 없어(0.0.4에서 관련 있는 유일한 원인인
  `touchType` 오판은 고쳤다), 기기/OS 쪽의 스타일러스 팜 리젝션(예: 삼성 S펜 "화면 터치
  무시" 설정)일 가능성이 높다고 보고 있다 — 사실이라면 웹 페이지 JS로는 우회할 수 없다.
  확정되기 전까지는 미해결로 남긴다.
